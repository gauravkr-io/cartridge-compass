## Cartridge Compass (managed block, version {{VERSION}})

This workspace uses Cartridge Compass, an SFCC project kit, at `{{KIT}}`. This block is regenerated by `node {{KIT}}/bin/sfcc-kit.mjs setup`. Write project rules outside it.

### Orient before acting

1. Read `docs/ai/generated/project-context.md`: repositories, their architecture (configured or detected, with confidence), and what is not configured.
2. Read `{{KIT}}/knowledge/INDEX.md` and open only the knowledge files for this task and architecture. Never load the whole knowledge folder.
3. For site and cartridge questions read `docs/ai/site-map.md` and `docs/ai/project-map.md` if they exist. If they do not, say so and suggest `/sfcc-kb-init`. Do not guess the structure.

Before changing code, answer: which repository, which architecture, which related repositories, which cartridges and in what precedence, which existing implementation, which conventions, which Salesforce APIs apply, what is known and unknown, which files must be read, what is the smallest safe change, and how it will be validated.

### Priorities

Project conventions, then existing architecture, then existing implementation patterns, then official Salesforce guidance, then generic best practice. Search for an existing utility, service, model, middleware, hook, controller, script, template or test before writing a new one. Do not replace a deliberate project design because another looks cleaner. Mark any deviation as a proposal.

### Resolution rules

- Controllers: the platform uses the first `controllers/<Name>.js` on the site's cartridge path (left wins) without checking that it contains the requested function. A missing function errors. It does not fall through. Pipelines are used only if no controller of that name exists anywhere on the path.
- SFRA routes can be assembled from several files through `server.extend(module.superModule)`. Read the whole chain.
- Templates and `*/cartridge/...` modules: first match, left wins.
- Hooks: every cartridge on the path that registers an extension point runs, in path order. A Shopper API hook that returns a value skips later hooks and the system implementation.
- For shared cartridges, checkout, payment, hooks, jobs or metadata, run the sfcc-change-impact skill before editing. For code that exists in both SGJC and SFRA, use sfcc-hybrid-migration.

### Never invent

Never invent SFCC APIs, hooks, metadata, Business Manager settings, cartridge paths, site IDs, endpoints or configuration. Verify, state the uncertainty, or ask.

- Used the same way in this project: existing usage proves the API exists, not that it is current. Before copying it into new code, check deprecation with `b2c docs read <Class>`.
- Not yet used here: `b2c docs read dw.<package>.<Class>`.
- OCAPI or SCAPI endpoints, hooks, custom APIs, import XML: `b2c docs search "<topic>" --category commerce-api`, `b2c docs schema <name>`.
- Cannot verify: say "This could not be verified from the project code or official Salesforce documentation" and do not write code that depends on it.

OCAPI is deprecated (April 2026). Do not add new OCAPI endpoints or OCAPI-only settings without the user's explicit agreement. Hook extension points named `dw.ocapi.shop.*` are shared with SCAPI and are not OCAPI-only.

### Missing configuration

Anything shown as "not configured" or "unknown" is unknown. Continue with what is known, name the conclusions that depend on the missing value, and discover it from code or read-only tooling, or ask. Configured values in `docs/ai/repositories.md` override detection.

### Tools and safety

- Official plugins `b2c` and `b2c-cli` cover SFRA and platform patterns. Use the sfcc-sgjc skill for SGJC and pipelines.
- Run `b2c` from this workspace root or pass `--config`. The CLI searches upward for `dw.json`, so running it inside a repository can target a different instance.
- Instances in `dw.json` are sandboxes only. Never target staging or production unless the user asks in this session.
- Read-only commands (docs, list, logs) are fine. Anything that deploys, activates, imports, runs jobs, replicates, or changes cartridge paths, preferences, users or roles needs the user's go-ahead for that specific action, whether through the CLI or MCP tools.
- After changing routes, hooks, job steps, services, metadata, custom APIs or cartridge responsibilities, run the sfcc-kb-sync skill. After adding or removing a repository, run `node {{KIT}}/bin/sfcc-kit.mjs sync`.

### Honesty, secrets, git

- Label non-trivial claims in docs and explanations: `[code]`, `[docs]`, `[inferred]`, `[unknown]`. If a design reason is not in code, commits or docs, write "Reason unknown. Do not assume intent."
- Never open or copy `dw.json`, `.env*`, keys or certificates. Reference where a credential is configured, never its value.
- Never reset, revert, force-push or discard changes you did not make without explicit instruction. Never run `git init` in this workspace root.
